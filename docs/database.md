# Trainer Manager · ฐานข้อมูล (เวอร์ชันแรก)

ไฟล์จริงอยู่ที่ `supabase/migrations/` · ใช้กับ Supabase (Postgres) · ทดสอบบน Postgres 16 ผ่านแล้ว

## ภาพรวม 36 ตาราง แบ่ง 6 กลุ่ม

### 1. คน
| ตาราง | เก็บอะไร |
|---|---|
| profiles | ทุกคนที่สมัครแอป: UID (เริ่ม 100001), ชื่อ, เบอร์, อีเมล, วันเกิด, ส่วนสูง, เป็น Super Admin ไหม, ใช้งาน/ระงับ |
| subscriptions | แผนที่จ่าย: ผู้ใช้ / เทรนเนอร์ / ยิม · ทดลองถึงวันไหน · จ่ายถึงวันไหน |
| consents | การกดยินยอม PDPA (ทุกคน) และการถอนความยินยอม |

### 2. ยิม (เคาน์เตอร์)
| ตาราง | เก็บอะไร |
|---|---|
| gyms | ยิม: ชื่อ สาขา ที่อยู่ หมุดแผนที่ เวลาเปิด วันปิดประจำ ราคาขาจร |
| gym_staff | ใครทำงานยิมไหน บทบาท Owner / Admin / Operator / เทรนเนอร์ |
| gym_holidays | วันหยุดพิเศษ (เช่น ปีใหม่) |
| membership_plans | ราคาแพ็กสมาชิกของยิม (1 / 3 / 6 เดือน / 1 ปี) |
| members | รายชื่อสมาชิกของยิม · มีหรือไม่มีแอปก็ได้ · รหัส M-xxxx · ติ๊ก "PT อย่างเดียว" ได้ |
| memberships | การซื้อ/ต่ออายุแต่ละครั้ง: วันเริ่ม วันหมด ราคา จ่ายแบบไหน ใครขาย |
| member_freezes | พักสมาชิกรายคน |
| checkins | การเช็กอินเข้ายิม |
| walkins | ขาจรรายวัน (ไม่มีชื่อ) |

### 3. เทรนเนอร์และลูกเทรน
| ตาราง | เก็บอะไร |
|---|---|
| trainer_profiles | โปรไฟล์เทรนเนอร์: ประวัติ ใบรับรอง ช่องทางติดต่อ ความยาวนัดเริ่มต้น เปิดให้ค้นหาไหม |
| trainer_clients | เทรนเนอร์ ↔ ลูกเทรน (เหมือนเป็นเพื่อนกัน) · ลบได้โดยบัญชีลูกเทรนยังอยู่ |
| pt_prices | ราคาแพ็ก PT รายเทรนเนอร์ |
| pt_packages | แพ็ก PT ที่ลูกเทรนซื้อ: กี่ครั้ง วันหมด ราคา |
| pt_package_ledger | ทุกการตัดครั้ง/แถม/คืน/ขยายวัน · แก้มือต้องใส่เหตุผล · ลบไม่ได้ (เป็นประวัติ) |
| trainer_availability | เวลารับเทรนแต่ละวัน |
| trainer_leave | วันลา / ลากะทันหัน |
| appointments | นัด: เวลา ความยาว 30/45/60/90 นาที สถานะ เวลาเริ่มจริง |
| reschedule_requests | คำขอเลื่อนนัดจากลูกเทรน |
| invites | คำเชิญ (ลิงก์ / ค้นหา / QR) |

### 4. การเทรน
exercises (คลังท่า) · programs + program_exercises (โปรแกรม/เทมเพลต/วางล่วงหน้า) · workouts + workout_sets (บันทึกการเทรน ทั้งกับเทรนเนอร์และเล่นเอง)

### 5. อาหารและร่างกาย
foods (ฐานข้อมูลอาหารไทย + เมนูที่สร้างเอง) · food_favorites · meals + meal_items (มื้อ / รายการในมื้อ / รูป / มาจาก AI ไหม) · meal_comments (คอมเมนต์จากเทรนเนอร์) · nutrition_targets (เป้าแคล/มาโคร เก็บทุกครั้งที่เปลี่ยน = ประวัติ) · body_measurements · progress_photos

### 6. ระบบ
audit_log (ใครทำอะไรเมื่อไร)

## ใครเห็นอะไร (ทดสอบแล้ว)
| | รูป/อาหาร/การเทรน | รายชื่อสมาชิกยิม | แก้แพ็ก PT |
|---|---|---|---|
| ตัวเอง | ✓ ของตัวเอง | เฉพาะของตัวเอง | – |
| เทรนเนอร์ | ✓ เฉพาะลูกเทรนตัวเอง | เฉพาะลูกเทรนตัวเอง | ✓ ของลูกเทรนตัวเอง |
| เทรนเนอร์คนอื่นในยิม | ✗ | ✗ | ✗ |
| เจ้าของยิม (Owner) | ✓ ทุกคนในยิม | ✓ | ✓ |
| Admin / Operator | ✗ | ✓ | Admin ✓ · Operator ขายแพ็กได้ |
| คนนอก | ✗ | ✗ | ✗ |
| Super Admin | ✓ ทั้งหมด | ✓ | ✓ |

ผลทดสอบเพิ่มเติม:
- เทรนเนอร์ลบลูกเทรนออก → เห็นข้อมูลไม่ได้ทันที บัญชีลูกเทรนยังอยู่
- ผู้ใช้ตั้งตัวเองเป็น Super Admin ไม่ได้
- เช็กอินออฟไลน์ที่ส่งซ้ำ ระบบไม่บันทึกซ้ำ
- สมาชิกไม่มีแอปที่สมัครแอปทีหลังด้วยเบอร์เดิม → ระบบเชื่อมให้อัตโนมัติ
- 1 เดือน เริ่ม จ. 12 ต.ค. ยิมปิดวันอาทิตย์ → หมด 16 พ.ย. (ไม่นับวันอาทิตย์)
- เพิ่มวันหยุดพิเศษ → วันหมดอายุสมาชิกและแพ็ก PT เลื่อนเฉพาะวันที่ยิมควรเปิด

## กติกาที่ฝังในฐานข้อมูล
- ครั้ง PT คงเหลือ = จำนวนแพ็ก + รวมทุกบรรทัดใน ledger (ไม่มีใครแก้ตัวเลขตรง ๆ ได้)
- ต่ออายุก่อนหมด → เริ่มต่อจากวันหมดเดิม (`renewal_start`)
- คำนวณวันหมด ไม่นับวันปิดประจำและวันหยุดพิเศษ (`calc_end_date`)
- รูปเก็บที่ `private/<user id>/...` ใช้กติกาเดียวกับตาราง
